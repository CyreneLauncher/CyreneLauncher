# Guarded Cacio source adaptations

`series.json` is the reviewable patch series; `tools/build_cacio.py` applies each source change to a fresh extraction of the pinned archive. Every changed text hunk must occur exactly once. CTCScreen additionally requires the entire Android static initializer to be the final class member before removing only that block. Missing, duplicated, or moved code fails the build without deleting unrelated members.

The patch series removes CTCScreen's Android `LD_LIBRARY_PATH`/`libpojavexec_awt.so` initializer; selects one JVM-local Clipboard and excludes Android CTCClipboard native hooks; excludes unused CTCPreloadClassLoader and FontManagerUtil; and makes unsupported Desktop file/URL actions throw IOException while not advertising About/Quit handlers that would be discarded (direct setter calls throw UnsupportedOperationException).

The Task 2 patches also expose synchronized fixed-size screen initialization for the bootstrap, provide the screen color model from CTCToolkit, and remove Cacio's Linux FcFontManager override so the JDK's OrbisFontManager remains selected. The build emits `orbis-desktop-adapter.jar` and exact `launch-options.txt`; all three bundle JARs must be on the startup system class path before calling `DesktopBootstrap.initialize()`. Application JARs are then loaded with `DesktopBootstrap.createApplicationLoader`, whose parent is the platform loader and whose only system-provider delegation is the reserved Cacio package.

Task 3 serializes each screen Graphics operation and full inherited convenience operation with one CTCScreen-owned lock. The lock is shared by all create clones and surrounds WindowClippedGraphics on both sides so its state and compound convenience drawing are serialized. Snapshot copying and CTCRobotPeer pixel reads call BufferedImage.getRGB under that lock; arrays returned by RobotPeer are newly allocated and the full-frame API requires caller storage. Custom Paint, Composite, and ImageObserver implementations may be invoked inside the serialized Graphics operation by AWT itself; the adapter does not explicitly dispatch events or call application code while taking the lock. The fixed desktop session exposes caller-owned full-frame copying; its lifecycle and publication sequence are coordinated with screen painting.

Round 1 lock-order fix: the successful-copy sequence and submission-closed flag now live on CTCScreen and are read or changed only under the same reentrant `screenLock` used by painting. `copyCurrentScreenARGB(int[])` returns the sequence after a successful full copy; `closeFrameSubmission()` closes only adapter snapshot submission under that lock. `DesktopSession` has no lifecycle monitor and delegates directly, so Java2D callbacks cannot form a session-monitor/screen-lock cycle. Robot and offscreen screen drawing remain available after submission closes. The internal Cacio copy helper therefore returns `long` (the public `DesktopSession.copyFrame` contract remains unchanged).


The integrated input patches install a safely published optional `CacioEventSource` delegate before toolkit startup. Its narrow `PollingEventSource` method may return null on a finite poll; the public `getNextEvent` loops until a real event and never dispatches null. The existing daemon Cacio pump polls local work for at most 2ms and then the native delegate for at most 2ms. Interrupts exit explicitly with interrupt status restored. Installation and source singleton creation are synchronized.

Retained local events are bounded to 256: 255 queue entries and one reserved paint invalidation. Same-source, same-ID paint rectangles coalesce by union while retaining the queue slot. Queue polling and coalescing share the source monitor so an event cannot be mutated after dequeue. On full queue, a paint request for the sole virtual screen becomes a full-screen invalidation in the reserved slot and is served next; later overflow paint replaces it with the same full-screen invalidation. Other producer overflow raises an explicit exception rather than silently losing a Robot key/button release. FullScreenEventPump sends paint invalidations through managed repaint, which posts normal AWT paint work. The original CTCScreen local paint producer is commented-out legacy code and removed with its mutable frame helper. The active normal paint path remains managed-window repaint; native input has no second queue.

`CTCScreen.getEventRoot()` exposes the existing public `ScreenManagedWindowContainer`, with no screen-lock acquisition. FullScreenWindowFactory eagerly establishes that single root; its source wrapper recognizes managed roots and otherwise preserves its PlatformScreen mapping. All desktop input still enters FullScreenEventPump, then AbstractManagedWindowContainer mouse hit testing / FocusManager key routing. EventData now uses explicit buttons on press/release/click and NOBUTTON for movement/drag/enter/exit; wheel sign and magnitude have their own field. The Robot producer's preexisting down masks are converted to button IDs at its narrow EventData boundary.

Input maps USB HID letters/digits, punctuation, editing/navigation, F1–F24, keypad and modifiers. Orbis keyboard modifier constants were checked in the SDK `_types/keyboard.h`: left Ctrl/Shift/Alt/Meta are 1/2/4/8 and right are 16/32/64/128. Separate MODIFIERS packets synthesize the eight modifier key transitions using HID IDs224–231. Unknown HID values map VK_UNDEFINED and never generate printable text. Ctrl ASCII typed characters normalize to controls; Alt/Meta suppress printable typed characters, with right Alt treated as AltGr. Initial Backspace generates pressed+typed U+0008, repeat Backspace TEXT generates repeat pressed+typed U+0008, and initial Return/Tab generate pressed+typed LF/TAB. Swing DefaultEditorKit excludes control characters from its default insertion action, so pressed bindings perform one edit.

Mouse bit index0→BUTTON1, index1→BUTTON3, index2→BUTTON2 is inferred from the native layout and awaits PS4 confirmation; other bits are ignored. Native screen coordinates remain unchanged until upstream hit testing converts them to window coordinates. A genuine press/release produces one click only when no movement occurred, coordinates match, and the elapsed time is at most 500ms. Any motion while held cancels click eligibility; RESET releases/reconciled presses never create clicks or popup triggers. Multi-click counts are currently always one. Wheel rotation preserves the native signed integer, pending platform direction confirmation.

RESET drains at most 256 key releases +256 reconciled presses +3 button releases +3 presses (518 events) in fixed 576-slot synthesized storage before another native read. Modifiers join the same 256-entry key state and are reconciled from the snapshot's separate modifier mask. Reconciliation suppresses typed text and clicks; synthesized KEY_PRESSED events may invoke application or Swing pressed bindings again, including editing actions. Synthetic key/button releases are real AWT events and may also invoke application actions, including a Swing button action on release. Reconciliation is not side-effect-free. An inactive reset is empty after releases. Native monotonic microseconds are anchored to Java wall-clock milliseconds on the first event and clamped nondecreasing.

No cursor drawing was found in upstream managed containers, ManagedWindow, CTCScreen or CacioComponentPeer; updateCursorImmediately is a TODO. Consequently no cursor-disable hunk is needed. FullScreenWindowFactory ignores owner windows; ManagedWindow title/resizable/blocked and several stacking methods remain TODO, and hit testing has no pointer capture. Existing decoration selection does not establish reviewed movement, resize or modality support. Multiple application-requested windows follow existing visibility/focus/hit-test routing only; full AWT/window behavior and hardware acceptance remain pending.

DesktopRuntime validates artifacts and native capability words before AWT, installs the delegate, initializes DesktopBootstrap once, and starts native services plus one daemon frame worker once. Bootstrap then exercises the JDK-owned drawing/font/JPEG/ICC/native-filter providers before session publication or application initialization; it rejects ImagingLib's silent fallback and empty scaler output. The worker reuses one 921600-element frame, submits synchronously at most 30Hz, never queues frames and skips missed deadlines. The first publication failure emits one diagnostic per session while retaining the prior native frame. Five consecutive publication failures stop desktop services and return console focus with one further diagnostic. Success clears the consecutive count but does not rearm the first-failure log. Input failure also stops publication and explicitly exits the pump. Application main returning does not close workers or the application loader. Shutdown interrupts workers, stops native publication/focus under the lifecycle monitor, and joins each worker for at most 500ms; it never calls DesktopSession.close or waits for the Java drawing lock. A blocked daemon snapshot worker may survive until JVM exit, but its stop check and native state guard prohibit later publication. Native service storage stays launcher-owned and restart stays unsupported.

These source transformations preserve the pinned archive's original Oracle/Sun copyright headers and GPL-2.0-only WITH Classpath-exception-2.0 provenance (repository/commit/archive SHA256 in `tools/cacio-source.json`). The existing CTCEventSource has no header in the pinned archive; its generated adaptations retain that source provenance and the export includes the upstream LICENSE.


Local queue delivery takes priority over native delegate polling. A continuously nonempty Robot/local event queue can starve native input and reset recovery; the 2ms waits are idle polling bounds, not a native delivery latency guarantee under that workload. Retention remains bounded and no fairness guarantee is claimed.
Fairness is deferred for this milestone; supporting sustained Robot/local input requires later source alternation or a bounded local-event quota.


Review fix round1 wraps the complete Cacio pump run loop in try/finally so every exit clears AWTAutoShutdown busy state, including loop-boundary interruption and uncaught errors. InterruptedException restores interrupt status before exit. DesktopRuntime rechecks its monotonic frame deadline and stop/interruption state after every park wakeup, so spurious wakes cannot trigger early submission; its existing completion-based scheduling and single frame remain intact.
